### 1.3 Boot structure (Limine)

- Config generated by `limine-update` from two files:
  - `/etc/default/limine` — `KERNEL_CMDLINE[default]`, `ESP_PATH`, (a `BOOT_ORDER` copy that is **ignored**)
  - `/etc/limine-entry-tool.conf` — **authoritative for `BOOT_ORDER` and `ENABLE_SORT`** (load order: `/usr/share/limine-entry-tool.d` → `/etc/limine-entry-tool.conf` → `/etc/limine-entry-tool.d` → `/etc/default/limine` highest priority)
- `ENABLE_SORT=yes` is required for `BOOT_ORDER` reordering to take effect (with `no`, menu order/`default_entry: 2` picks the stock kernel)
- Boot order: `*lts, *, *fallback, Snapshots`
- Bootable btrfs snapshots appear under an expandable **Snapshots** submenu, titled by their pacman transaction description (e.g. `pacman -S memtest86+` — easy to mistake for a real memtest entry! Booting one mounts root as an overlay in cowspace; changes don't persist)
- **Memtest86+ has NO auto-generated menu entry in this tooling version** — manually appended to `/boot/limine.conf` (see §2.4), followed by `sudo limine-enroll-config` (required: `ENABLE_VERIFICATION=yes` enrolls a config hash into the bootloader binary)

## 2. All Local Modifications (reproduction reference)

Every deviation from stock CachyOS, with exact contents.

### 2.1 Kernel command line — `/etc/default/limine`

```ini
ESP_PATH="/boot"
KERNEL_CMDLINE[default]+="quiet nowatchdog splash rw rootflags=subvol=/@ root=UUID=da20171a-7e4b-4e57-af28-ec831833c51c i915.enable_psr=0 i915.enable_dc=0 mem_sleep_default=s2idle libata.force=1.00:nolpm intel_idle.max_cstate=3 pcie_aspm=off"
BOOT_ORDER="*lts, *, *fallback, Snapshots"
```

Rationale per flag (all anti-freeze mitigations, applied in order of discovery):

| Flag | Purpose | Status |
|---|---|---|
| `i915.enable_psr=0` | Disable Panel Self-Refresh (Kaby Lake silent-freeze bug) | Applied Aug 30; big improvement (see log) |
| `i915.enable_dc=0` | Disable display C-states | Applied Aug 30 |
| `mem_sleep_default=s2idle` | Fix HP S3 resume black screen (lid issue) | Applied Aug 30; lid fix verified |
| `libata.force=1.00:nolpm` | Disable SATA link power mgmt (SMR HDD idle wedges) | Applied Sep 5 |
| `intel_idle.max_cstate=3` | Cap CPU idle at C3 (deep-sleep wedge prevention) | Applied Sep 6 (soak test) |
| `pcie_aspm=off` | Disable PCIe link power saving | Applied Sep 6 (partially redundant: BIOS FADT already declares ASPM unsupported) |

After any edit to either config file: **`sudo limine-update`** (regenerates `/boot/limine.conf`), then **`sudo limine-enroll-config`** if `/boot/limine.conf` was edited directly.

### 2.2 `/etc/limine-entry-tool.conf`

```ini
ENABLE_VERIFICATION=yes
BOOT_ORDER="*lts, *, *fallback, Snapshots"
ENABLE_SORT=yes
FIND_BOOTLOADERS=yes
ENABLE_UKI=no
```

(Stock had `ENABLE_SORT=no` and `BOOT_ORDER="*, *fallback, Snapshots"`.)

### 2.3 Sysctls

`/etc/sysctl.d/90-sysrq.conf` — full Magic SysRq so freezes are rescuable/diagnosable:

```
kernel.sysrq = 1
```

`/etc/sysctl.d/90-dirty.conf` — cap dirty-page writeback for the SMR HDD (prevents multi-second UI stalls during package installs):

```
vm.dirty_background_bytes = 67108864
vm.dirty_bytes = 268435456
```

### 2.4 Manual Memtest86+ boot entry — appended to `/boot/limine.conf`

```
/Memtest86+
    protocol: linux
    kernel_path: boot():/memtest86+/memtest.bin
```

Then `sudo limine-enroll-config`. **Note:** re-append + re-enroll after any `limine-update` regeneration if the entry disappears. Package `memtest86+` 7.20 installed (binary at `/boot/memtest86+/memtest.bin`).

### 2.5 WiFi powersave off — `/etc/NetworkManager/conf.d/wifi-powersave-off.conf`

```ini
[connection]
wifi.powersave = 2
```

(2 = disable. `sudo systemctl restart NetworkManager` after editing; verify `iw dev wlan0 get power_save` → off.)

### 2.6 XFCE power settings (anti-freeze soak test, since Sep 6)

- **Power Manager → Display: "Blank after" = Never** (AC + battery)
- **Screensaver: disabled** (auto-lock off; manual `xflock4` still available)
- **XFCE compositor: disabled** on Sep 7 for an i915 page-flip isolation soak test (`xfconf-query -c xfwm4 -p /general/use_compositing -s false`)

### 2.7 Not modified / defaults kept

- zram-generator: `zram-size = ram`, zstd, priority 100 (CachyOS default)
- swappiness 150 (CachyOS default, good for zram)
- No disk swap (SMR HDD would thrash)

### 2.8 Verification commands (post-reboot checklist)


## 3. The Crash Issue

### 3.1 Symptoms (consistent across all occurrences)

- **Total hard freeze**: mouse, keyboard, everything dead; screen shows last frame
- **Zero log output**: no kernel panic, no OOM, no MCE/EDAC, no thermal, no GPU error, no IO stall — journald simply stops. pstore/EFI empty (kernel never panicked — it *wedged*)
- **Magic SysRq (R-E-I-S-U-B) did nothing** at least once (Sep 6) — note caveat: wireless USB keyboard, so a dead USB/xHCI path would also block SysRq even with a live CPU
- Machine recovers only via power button; filesystem always consistent (btrfs + snapshots)
- Frequency varied wildly: 20 min → 6 min → 5.5 days

### 3.2 Crash log (chronological)

| # | Date | Boot uptime | Context / final log entries |
|---|---|---|---|
| 1 | Aug 30 ~20:41 | ~20 min | 2 min after `pacman -S ghostty` + snapshots; froze 2s after launching ghostty |
| 2 | Aug 30 ~21:19 | ~31 min | After flatpak installs; all XFCE apps "unresponsive" (at-spi) at final second |
| 3 | Sep 5 16:23 | **5.5 days** | Idle; screensaver unlock 9 min prior; brightness adjustments 16:07–16:13 |
| 4 | Sep 5 17:15 | 22 min | LTS manually selected; ~2 min after opening ghostty surface |
| 5 | Sep 5 17:32 | **6 min** | LTS + i915 flags; ghostty open → **kernel 7.2.2 ruled out** |
| 6 | Sep 6 ~23:22 | ~24 h | **No ghostty open** (ghostty ruled out); REISUB tried, no luck; screensaver unlock 10s before last log |

### 3.3 Eliminated causes (with evidence)

| Cause | Evidence eliminating it |
|---|---|
| Kernel 7.2.2 regression | Crash #5 on LTS 6.18 |
| RAM instability | memtest86+ 7.20: **2 full passes, 0 errors** (Sep 6). Mixed-stick config (4+8 GB) was the top suspect |
| OOM / memory pressure | 3.5/12 GB used, 11.6 GB zram unused at all times |
| Overheating | ~50 °C idle, no thermal events in any log |
| Disk / SMR IO stalls | Crashes occur idle; SMART passed with 0 realloc/pending/offline-uncorrectable/CRC sectors and no logged errors. Device Statistics retains 5 reported uncorrectable errors and 3 command-completion resets, so the disk is healthy-looking rather than perfect. (SMR still causes UI stalls during installs — separate QoL issue) |
| i915 PSR / display C-states | Mitigated Aug 30 → uptime jumped 20 min → 5.5 days (these WERE a real component) |
| SATA LPM | Disabled (`nolpm`); crash #6 still occurred |
| ghostty (GPU-accelerated terminal) | Crash #6 with no ghostty. **Exonerated** |
| Lid/S3 resume | Separate issue, fixed with `s2idle` (black screen on lid-open; machine ran but no display) |

### 3.4 Observations / patterns (unproven)

- Crashes #3 and #6 had screensaver unlock / display-wake events seconds-to-minutes before the freeze
- "Xfce configuration service" (`xfsettingsd`) restarts correlate with display-wake events and appear near several crashes — **but occur ~11×/day routinely**, so weak signal only
- HP firmware demonstrably buggy on this machine: ACPI `_SB.WMID.*` method errors, `hp-wmi: Failed to apply initial fan settings: -22`, ACPI thermal "Invalid critical threshold"
- Windows (historically) never froze on this hardware — consistent with a firmware bug only Linux's ACPI/EC paths trigger

### 3.5 Current hypotheses (ranked)

1. **XFCE compositor/i915 DRM page-flip interaction** — `kworker/u33:3+i915_flip` remained in `D` state for ~24 minutes; disabling XFCE compositing made it disappear immediately while direct Intel rendering remained accelerated. The underlying eDP/firmware trigger is still unknown.
2. **HP EC/ACPI firmware wedge** (display/backlight/idle path) — fits broken ACPI methods, silent platform-level hang, Windows-vs-Linux asymmetry. **Test: BIOS flash to F.23+ if available**
3. **Board-level degradation** (VRM/caps, 2017-era hardware) — unfalsifiable in software; outcome of soak test + BIOS flash informs this
4. Remaining idle-power interaction (deep C-states / ASPM / WiFi doze) — **all now disabled, soak test in progress**

### 3.6 Investigation log (dated)

- **2026-08-30** — Fresh CachyOS install. Two freezes (~20/31 min) after package installs. Investigated: journal, SMART, temps, kernel logs. Applied `i915.enable_psr=0 i915.enable_dc=0`, sysrq, dirty-bytes caps.
- **2026-08-30 → 09-05** — 5.5 days stable. Lid-resume black screen reported; fixed with `mem_sleep_default=s2idle`.
- **2026-09-05** — Crash #3 (idle, 5.5-day uptime). LTS default boot pursued (`ENABLE_SORT=yes` discovered as the missing piece); `libata.force=1.00:nolpm` added. Crashes #4 and #5 → kernel ruled out.
- **2026-09-06** — memtest86+ 2 passes clean (RAM ruled out). Crash #6 (no ghostty, REISUB dead) → ghostty ruled out. Research: 15-cc6xx M.2 slot is **SATA-only**; BIOS F.22, line EOL. Applied full idle-PM shutdown: `intel_idle.max_cstate=3 pcie_aspm=off`, WiFi powersave off, screen blanking/screensaver disabled. **Soak test started Sep 6 ~23:58.**
- **2026-09-07** — Observed `kworker/u33:3+i915_flip` (PID 14654) stuck in `D` state for ~24 minutes with no matching kernel error. Disabling XFCE compositing made the worker disappear immediately; direct Intel rendering remained accelerated. This is the strongest evidence so far for an XFCE compositor/DRM page-flip interaction. Compositing is left disabled for the soak test. Root diagnostics confirmed `enable_psr=0`, `enable_dc=0`, `enable_hangcheck=Y`, `error_capture=Y`, and enabled GPU reset; no DRM or i915 error state was collected. SMART passed with no logged errors, but device statistics showed 5 reported uncorrectable errors and 3 command-completion resets.

## 5. Gotchas / Lessons Learned (this machine)

1. **Two config files for Limine**: kernel cmdline in `/etc/default/limine`; boot order/sorting in `/etc/limine-entry-tool.conf`. Editing the wrong one silently does nothing.
2. **`ENABLE_SORT=yes` required** for `BOOT_ORDER` to reorder kernels; `default_entry: 2` is hardcoded by the generator.
3. **`limine-enroll-config` must run after direct edits to `/boot/limine.conf`** (`ENABLE_VERIFICATION=yes`).
4. **Snapshot boot entries are named after pacman transactions** — "memtest86+" snapshot ≠ memtest. Snapshot boots are overlay-sandboxed (safe but non-persistent, and carry a stale cmdline).
5. **M.2 slot on 15-cc6xx is SATA-only** — NVMe drives will not work.
6. Mixed-stick RAM (4+8 GB) was top suspect; memtest cleared it. Never skip memtest on freeze investigations.
7. REISUB failing on a wireless-USB keyboard does not prove the CPU is wedged — the USB stack itself may be part of the hang.
