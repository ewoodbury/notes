# Post-SSD Performance Results

This is the clean post-upgrade measurement set for the HP Pavilion 15-cc6xx, collected on 2026-09-12 at 14:47-14:52 PDT on branch `luna-5.6-after-clean`. The replacement drive is a Timetec `35TT2280SATA-512GB`, serial `QYR260622B5D0231`, now mounted as `/dev/sdb2`.

## Result Summary

| Metric | HDD before | SSD after | Change |
|---|---:|---:|---:|
| Direct sequential write, 512 MiB | 69.5 MB/s | 169 MB/s | 2.43x faster |
| Direct sequential read, 512 MiB | 127 MB/s | 292 MB/s | 2.30x faster |
| Direct 4 KiB sequential read | 59.7 MB/s | 76.3 MB/s | 1.28x faster |
| `fio` sequential write, 1 MiB QD1 | 98.6 MiB/s | 224 MiB/s | 2.27x faster |
| `fio` sequential read, 1 MiB QD1 | 69.6 MiB/s | 279 MiB/s | 4.01x faster |
| `fio` random read, 4 KiB QD1 | 138 IOPS | 7,436 IOPS | 53.9x more IOPS |
| `fio` random read, 4 KiB QD1 average latency | 7.195 ms | 0.1335 ms | 53.9x lower |
| `fio` random read, 4 KiB QD1 p99 | 18.744 ms | 0.192 ms | 97.6x lower |
| `fio` random read, 4 KiB QD32 | 138 IOPS | 55,295 IOPS | 401x more IOPS |
| `fio` random read, 4 KiB QD32 average latency | 230.88 ms | 0.578 ms | 399x lower |
| `fio` random 70/30 total IOPS | 94 IOPS | 7,392 IOPS | 78.6x more IOPS |
| `ioping` direct 4 KiB average | 10.6 ms | 0.2107 ms | 50.3x lower |
| Create 1,000 empty files | 93 ms | 29 ms | 3.21x faster |
| Stat 1,000 files | 20 ms | 11 ms | 1.82x faster |
| Remove 1,000 files | 35 ms | 17 ms | 2.06x faster |
| Warm Firefox executable proxy | 55.9 ms | 27.4 ms | 2.04x faster |
| Warm Chromium executable proxy | 66.9 ms | 33.0 ms | 2.03x faster |
| Warm Thunar executable proxy | 85.8 ms | 25.9 ms | 3.31x faster |
| Warm Ghostty executable proxy | 78.0 ms | 37.8 ms | 2.06x faster |

The random-I/O and latency improvements are the most important day-to-day result. The SSD also removes the HDD queue-depth failure mode: QD32 random reads increased throughput instead of keeping the same IOPS while average latency rose to 231 ms.

## Detailed Measurements

### Direct `dd`

The same 512 MiB incompressible `/dev/urandom` workload and direct I/O mode were used as in the HDD baseline:

```text
dd if=/dev/urandom of=.../random-data.bin bs=1M count=512 oflag=direct conv=fsync
536870912 bytes, 3.17074 s, 169 MB/s

dd if=.../random-data.bin of=/dev/null bs=1M iflag=direct
536870912 bytes, 1.8398 s, 292 MB/s

dd if=.../random-data.bin of=/dev/null bs=4K count=131072 iflag=direct
536870912 bytes, 7.03765 s, 76.3 MB/s
```

### `fio` 3.42

All tests used a 512 MiB file, direct I/O, `libaio`, and one job. Random tests ran for 30 seconds after a 5-second ramp period.

| Workload | Result | Latency details |
|---|---:|---|
| Sequential write, 1 MiB, QD1 | 224 MiB/s, 223 IOPS | average 4.431 ms; p99 10.432 us completion latency |
| Sequential read, 1 MiB, QD1 | 279 MiB/s, 278 IOPS | average 3.578 ms; p99 3.654 ms |
| Random read, 4 KiB, QD1 | 7,436 IOPS, 29.0 MiB/s | average 133.51 us; p95 165 us; p99 192 us |
| Random read, 4 KiB, QD32 | 55,295 IOPS, 216 MiB/s | average 578.04 us; p95 1.139 ms; p99 1.385 ms |
| Random 70% read / 30% write, 4 KiB, QD1 | 5,173 read + 2,219 write IOPS | read average 160.15 us; write average 72.90 us |

The sequential write latency percentile in the raw `fio` output is completion latency and excludes submission latency; the overall average total latency is the more useful number in the table.

### `ioping` and metadata

```text
ioping -D -c 30 -i 0 -s 4k /home/ethan/ssd-baseline-temp/fio-test.bin
29 requests completed in 6.11 ms, 116 KiB read, 4.75 k iops
min/avg/max/mdev = 152.1 us / 210.7 us / 301.5 us / 40.4 us
```

The warm-cache metadata probe created, stat'ed, and removed 1,000 empty files in 29 ms, 11 ms, and 17 ms respectively. It is useful as an application/filesystem reference but is not a cold-cache storage latency test.

### Application startup and CPU controls

`hyperfine --warmup 2 --runs 10` measured the same version-command executable proxies as before:

| Command | Mean | Standard deviation | Range |
|---|---:|---:|---:|
| `firefox --version` | 27.4 ms | 2.4 ms | 24.8-33.3 ms |
| `chromium --version` | 33.0 ms | 3.1 ms | 31.2-41.6 ms |
| `thunar --version` | 25.9 ms | 0.7 ms | 25.0-27.4 ms |
| `ghostty --version` | 37.8 ms | 3.6 ms | 35.0-44.5 ms |

The post-SSD SHA-256 reference was 241,660.45 kB/s at 256 bytes, 294,610.98 kB/s at 1 KiB, 329,992.55 kB/s at 8 KiB, and 380,141.77 kB/s at 16 KiB, compared with 156,630.84, 237,614.86, 275,948.43, and 284,916.44 kB/s before. This is a control metric, not an SSD effect; CPU frequency, thermal state, system load, or package/runtime differences account for it.

### Boot

```text
firmware 3.699 s + loader 17.192 s + kernel 1.380 s + initrd 2.140 s + userspace 10.901 s = 35.313 s
graphical.target reached after 9.487 s in userspace
```

The userspace portion and graphical-target time improved substantially from 18.308 s and 16.424 s to 10.901 s and 9.487 s. Total boot was slower in this run because the loader took 17.192 s versus 4.739 s before, so total boot is not a clean storage comparison. The critical chain reached `/dev/sdb2` in 4.260 s and also included `NetworkManager-wait-online.service` at 5.799 s.

## Reproduction Notes

- The post-SSD tests used the same direct-I/O file size, block sizes, queue depths, workloads, and tool versions as the improved HDD baseline wherever possible.
- The SSD benchmark directory was removed after testing; no generated files are part of the repository.
- SMART access was attempted without root privileges and produced no readable output in this session. Existing repository history contains the factory-fresh SMART result for this Timetec drive.
- The system was not completely idle: I/O pressure was high at capture. The strong random-I/O gap is far larger than this noise, but a future controlled rerun should stop background indexing and use a freshly booted system.
